# Player movement prediction

Enable `PlayerController.UseClientPrediction` on the host, either in the player prefab or before spawning it:

```csharp
player.GetComponent<PlayerController>().UseClientPrediction = true;
player.NetworkSpawn( connection );
```

The controller must be on the network root, in a 3D scene with fixed updates enabled, using default input controls and the built-in `MoveModeWalk`. All peers must use the same fixed-update frequency. The option defaults to false. Unsupported configurations are rejected on the host. This mode replaces rigidbody movement with a trace-based walking motor; it does not change the existing rigidbody controller when disabled.

The owner captures one command per fixed tick and immediately simulates it. Unreliable owner-only host RPCs carry redundant batches of old pending and recent commands. The host buffers commands by sequence, rejects duplicates, and runs them in order using its own fixed delta and movement settings. A bounded time budget permits catch-up after jitter without allowing commands to advance faster than host time.

The host publishes one synchronized value containing an epoch, owner, acknowledged command, complete motor state, movement settings, body dimensions, and fixed delta. The owner restores that state and replays unacknowledged commands. Remote players use the existing transform interpolation. `NetworkFlags.HostTransformAuthority` makes transform replication authoritative on the host while preserving owner control of input RPCs and ordinary sync properties. A predicting owner consumes the coherent motor snapshot instead of the separate transform snapshot.

Movement supports walking/running, crouching with headroom checks, jumping with cooldown and coyote time, gravity, collision sliding, standable slopes, stairs, and supporting-platform translation/rotation. Both predicted and authoritative positions are compared in the displayed platform frame so ordinary platform carry does not count as a correction or get smoothed away. Grounded corrections preserve the player's platform-local position in the client's displayed platform pose. Replay uses that displayed collision world rather than reapplying older absolute platform poses; clients never supply platform poses to the host. Supported movement commands encode their heading relative to the sampled support; each peer resolves that heading using its own support pose. Carry and reconciliation rotate motor velocity, wish velocity, and push momentum along with position. Pending contact responses are also rotated into the displayed support frame. Collision queries during replay use the current world. Native dynamic bodies are not rolled back. The host and owning client run native contact response after the trace motor, with native gravity and input integration disabled to avoid double movement. Collision displacement and decaying push momentum are included in authoritative motor state; remote players do not simulate contacts independently. The owner records each pending tick after native contacts, including its contact displacement and push velocity, and reapplies that response once during replay. These local contact records are never sent to the host. Supporting-platform friction is handled by trace carry rather than applying it again through native contacts. Swimming, ladders, seating, 2D movement, and custom movement modes need their own replayable simulation before opting in.

History and host input buffering are bounded to 128 commands. Exhausting history requests a fresh host epoch. Changing ownership, host, fixed delta, or enabling/disabling prediction resets the timeline. Host-side position changes are treated as teleports and start a fresh timeline. External `Jump` impulses must run on the host in prediction mode and also start a fresh timeline.

Simulation itself emits no events. Jump/landing gameplay callbacks run on the authority after first simulation; local animation and landing sound run outside replay. Corrections update collision state immediately and smooth a separate camera/renderer offset. Large corrections snap. `PredictionCorrections` counts positional corrections on the owning client.

Validation includes pure motor and history tests, serialized input/state exchanges, authority checks, and a two-scene host/client integration test with delayed and dropped input packets, dropped snapshots, and a host teleport. For manual testing, run a host and owning client with simulated latency/loss, enable the option in the player prefab, and compare `PredictionCorrections`, wall collisions, crouch headroom, slopes/stairs, jumps, moving platforms, and teleports.
